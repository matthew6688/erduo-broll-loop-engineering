# 数字人图片、动作与背景系统

更新时间：2026-08-26

## 1. 目标

在已经冻结的默认 Erduo B-roll 基线之外，建立一个可审查、可复用的数字人视觉层。这个视觉层只负责：

- 选择哪一种获授权人物图片或 Avatar look；
- 选择低风险、可预期的动作；
- 选择主持人独立背景；
- 在 Recipe 已批准的 presenter 窗口内替换真人画面。

它不修改原始 DesignMD、默认 B-roll 主题、B-roll 构图或动画语言，也不把数字人服务当成 B-roll 渲染器。

### 现役决定（2026-08-26）

- 只适配数字人的独立背景和“峰说”Logo；不修改 Erduo B-roll DesignMD、主题、版式和动画。
- 不采用 `screen-led` 或录屏覆盖路线。只允许三种已冻结的 presenter 模式：`original`、`avatar-center`、`avatar-split`。
- `avatar-split` 不是新主题：它以 presenter MP4 为全画幅基底，在人物另一侧叠加已经通过门禁的 9:16 B-roll，并使用柔和边界衔接；必要镜头仍可切换为全屏 B-roll。
- Presenter 与 B-roll 继续由 Recipe 的 `presenter|broll|mixed` 决定时间窗；`mixed` 窗口再由获批 presentation-mode 合同决定 `full|split` 呈现。
- 数字人身份、声音、口型、字幕与正式发布门禁保持不变。

## 2. 当前基线证据

当前冻结基线使用一张 1254×1254 的正面胸像，生成 1080×1920 数字人口播，并只在三个窗口出现：

- 0–6.04 秒：开场与主张；
- 23.46–26.70 秒：章节/逻辑转折；
- 62.74–67.90 秒：结论与行动号召。

数字人共出现 14.44 秒，占 67.9 秒成片的 21.3%。这个比例合理，证明“主持人只在有任务时出现、B-roll 承担主要解释”已经成立。

现有图片的优点是脸部清楚、正面、自然彩色、背景干净，口型稳定。局限也很明确：画面只包含头肩和少量胸部，双手不在输入中，因此不能稳定产生真实手势；三个窗口的景别、站位和表达状态几乎相同，人物节奏弱于真人原版。

## 3. 永久不变量

1. 本人及数字人必须保持自然彩色和自然肤色，永久禁止黑白、灰度、双色印刷或 duotone 处理。
2. Presenter 与 B-roll 只按 Recipe 和获批 presentation-mode 合同编排；人物、品牌背景和 Logo 始终属于 presenter 层，不进入或重绘 B-roll 源码。
3. 同一条旁白只能有一个 canonical audio；更换音频后必须重新生成口型并重新编译时间线。
4. 原始 DesignMD 和已验证 B-roll 不随数字人图片、动作或背景实验而变化。
5. 每次实验只改变一个维度，并进入新的 versioned production root；冻结基线不得原地修改。
6. 所有正式人物资产必须记录肖像授权、声音授权、用途、文件 hash 和审批状态。

## 4. 人物图片 / Avatar look 库

不要让一个头像承担所有场景。第一版只建立四种受控 look，每种都有明确用途。

| Look | 输入构图 | 站位 | 允许动作 | 用途 | 风险 |
| --- | --- | --- | --- | --- | --- |
| P1 Anchor | 腰部以上、双手自然可见 | 居中 | 小幅解释、点头 | 开场、结尾、重要判断 | 最低，默认 |
| P2 Left | 腰部以上、身体微向内 | 左三分之一 | 单手开放式解释 | 右侧留一句标题/关键词 | 低 |
| P3 Right | 腰部以上、身体微向内 | 右三分之一 | 单手开放式解释 | 左侧留一句标题/关键词 | 低 |
| P4 Close | 胸部以上、眼神正对镜头 | 居中 | 极小点头、自然眨眼 | 个人判断、信任、结论 | 低 |

暂不纳入稳定库：坐姿办公桌、拿手机、操作电脑、指向精确 UI、走动、交叉手臂、双手连续挥动。这些场景更容易出现手指、道具、接触关系和身体结构错误，必须作为单独实验，不能进入默认流水线。

### 图片采集规格

- 自然彩色，柔和主光，肤色准确；不要依赖生成后修复肤色。
- 最少 2048 像素长边；16:9 与 9:16 分别准备，不从同一张图强裁两种画幅。
- P1/P2/P3 必须完整包含双手、手腕和肘部；四肢不能在画面边缘被切断。
- 穿哑光纯色上衣，避免细条纹、密格纹、反光面料和大面积商标。
- 表情中性友善，嘴自然闭合或轻微微笑；避免露齿过多和夸张表情。
- 背景与人物轮廓必须有亮度/色相分离，头发不能融入深色墙面。

## 5. 动作词典

动作不是自由文本创作，而是一个小型白名单。每段 presenter 只允许一个主要动作意图。

| 动作 ID | 动作 | 适合内容 | 建议 expressiveness | 验收重点 |
| --- | --- | --- | --- | --- |
| A0 neutral | 正视镜头、自然眨眼、轻微呼吸 | 一般口播 | low | 头部漂移、嘴型、眼神 |
| A1 gentle-nod | 句末轻点头一次 | 确认、结论 | low | 不连续点头，不像机械摆动 |
| A2 open-hand | 一次小幅开放式手势 | 解释概念、提出建议 | low/medium | 手指完整，手不遮脸 |
| A3 count | 清楚但克制地表达“一/二/三” | 枚举 | medium | 数量是否准确；不准确即失败 |
| A4 contrast | 左右各一次小幅手势 | A/B 对比 | medium | 动作方向与画面语义一致 |

默认动作是 A0。A1/A2 通过两次不同脚本 canary 后才能升级为稳定动作。A3/A4 属于条件动作，只能在动作与文稿逐字匹配且人工验收通过时使用。

禁止动作：大幅挥手、持续指点、精确指向后加的文字/UI、拿不存在的道具、触摸桌面或屏幕、鼓掌、快速转身、来回走动、夸张情绪和连续重复手势。

## 6. 背景体系

### B0 Warm Neutral Studio — 回退基线

- 温暖米白/浅沙色墙面，轻微真实景深；
- 一盏柔和侧灯或模糊灯影，不能抢人物；
- 无文字、Logo、屏幕、书本标题或可读小物；
- 最适合 P1/P4，也最容易跨内容复用。

它延续现有肖像的优点，但增加空间深度，减少证件照感。当品牌科技背景不稳定时，回退到 B0。

### B1 FengTalk Technology Studio — Presenter 品牌背景候选

- 人物坐在深色哑光桌前，保持腰部以上和双手完整可见；
- 暖暗科技录影棚、深墨/炭黑吸音墙、Harbor Teal 实景灯光和少量暖灯；
- 后墙只出现一次准确品牌标识：`峰说`；不使用域名、二维码或联系方式；
- 左/右留屏版本允许一块低信息密度的抽象网络或数据屏，用于后续放简短关键词；
- 不加入边牧、机器人、线路板脸、蓝紫霓虹或漂浮全息 UI；它只是主持人背景，不改 B-roll。

B1 只用于 presenter source。即使获批，也不能进入 Erduo B-roll DesignMD。人物保持自然肤色，不能套品牌双色滤镜。

### B2 Founder Office — 条件背景

- 真实、克制的创作者/办公室环境；
- 背景虚化，桌面和屏幕不出现可读信息；
- 只用于经验、判断、幕后过程和个人观点，不用于所有视频。

首版不使用“蓝紫霓虹科技博主背景”。它容易变成通用 AI/SaaS 视觉，与默认 Erduo B-roll 竞争，也会给肤色和黑发边缘带来冷色污染。

## 7. 场景路由矩阵

| 文稿任务 | Presenter/B-roll | Look | 动作 | 背景 |
| --- | --- | --- | --- | --- |
| 前 3–6 秒提出问题或主张 | presenter | P1 或 P4 | A0/A2 | B0 |
| 个人经历、判断、态度 | presenter | P4 | A0/A1 | B0 或 B2 |
| 章节切换、总结上一段 | presenter | P1 | A1 | B0 |
| 流程、数据、列表、产品界面 | B-roll | 无人物 | 无 | 原始 DesignMD |
| A/B 对比 | 优先 B-roll；必要时 presenter | P1/P2/P3 | A4 | B0 |
| 结尾结论和 CTA | presenter | P1 | A1/A2 | B0 |

建议稳定区间：Presenter 15–30%，B-roll 70–85%。当前冻结基线的 21.3% 已在合理区间，不需要增加出镜时长来证明数字人的存在。

## 8. HeyGen 能力映射

HeyGen 当前 v3 Create Video 支持 Photo Avatar/Digital Twin、外部音频、16:9/9:16、背景、`motion_prompt`、`expressiveness`、背景移除，以及对支持 matting 的 Avatar 输出透明 WebM。这些能力只说明 API 可以接受参数，不代表任意输入图片都能可靠地产生指定手势。

因此 Provider 层应保存受控字段，而不是让每集自由写 prompt：

```json
{
  "presenterLookId": "P1",
  "actionId": "A0",
  "backgroundId": "B0",
  "aspectRatio": "9:16",
  "expressiveness": "low",
  "motionPrompt": "calm presenter, minimal natural head movement"
}
```

正式请求仍使用已经批准的外部 narration asset，保持本地 VoxCPM/真人录音为唯一声音真相。

## 9. Canary 与升级门禁

### 第一轮：只验证人物构图

同一段 8–12 秒旁白、同一 B1 背景、同一 A0 动作，对比 P1/P2/P3。批准站位、裁切、肤色、品牌文字和人物尺寸，不评估新动作。

### 第二轮：只验证动作

使用已批准的 Look+B1，分别生成 A0、A1、A2。每种最多两次实际生成；如果仍有手指、头部漂移、嘴型或动作语义错误，该动作保持实验状态。

### 第三轮：只验证背景

使用已批准的 Look+A0，对比 B1、B0、B2。不能同时换服装、人物站位或旁白。

### 第四轮：进入 Erduo 合成

只把已批准的一个组合接入新的 presenter source，再复用冻结 B-roll 和原 presenter windows 做三窗 canary。通过身份、口型、音轨、字幕、完整解码和视觉审片后，才允许成为新的 presenter visual profile。

### 失败条件

- 人物被处理成黑白/灰度或肤色明显失真；
- 手指数量、手部结构、衣服、面部身份或背景在同一段内不稳定；
- 动作与文稿语义不一致，或手势遮住脸/字幕；
- 背景出现乱码、伪文字、漂移物体、过强霓虹或喧宾夺主的运动；
- 口型不同步、音轨缺失/重复、人物窗口与 Recipe 不一致；
- 未记录使用 `erduo-broll-loop-engineering` Skill，或没有相应 sidecar/验证证据。

## 10. 已冻结的决定与下一步

曾生成 P1 居中、P2 左侧和 P3 右侧三组人物概念，但都未获审批。这些本地媒体包含用户肖像，按仓库规则不进入 Git 或公共文档资产，也不得自动进入生产。

当前已冻结三种生产方法：原装 `original`、数字人居中 `avatar-center`、数字人在旁边并复用竖屏 B-roll 的 `avatar-split`。框架、确定性 FFmpeg 集成测试和不可发布的版式演示已完成；仓库内尚无当前 Skill 绑定、可发布的 presentation-mode canary。下一步只用真实、已批准且口型正确的数字人 source 跑短 canary，由用户审片后再决定是否进入完整视频；B-roll 继续使用原始 DesignMD，不重新设计。

## 11. 竖屏 / YouTube 背景风格 canary v2

2026-08-26 曾按用户要求补充两个独立画幅和三种明显不同的背景风格：`dark-harbor-tech`、`warm-founder-lab` 和 `bright-future-editorial`。横屏图是重新构图，不是竖屏裁切、拉伸或补边。这组图片随后未获批准，现仅作为本地实验记录，不是现役路线。

所有图片都使用同一获授权彩色肖像作为严格身份参考，并使用现有 FengTalk Logo 作为样式参考；背景只允许“峰说”，不使用域名。图片仍是 presenter 背景候选，不是 B-roll 主题。仓库通过 `.gitignore` 阻止这组用户媒体被误提交。

### 画幅规则

- `vertical-short`：人物可居中或位于一侧；桌面下方必须保留字幕安全区；不得从横屏裁切。
- `youtube-landscape`：人物按横屏独立构图；不得从竖屏扩图直接冒充横屏母图，也不预留 B-roll inset 作为默认布局。
- 同一 profile 的两个画幅可以共享材质、色温、服装和品牌装置，但必须拥有不同文件 hash、审批和 Avatar canary。
- 后续每个 profile 只做 8–12 秒 A0 口播 canary；没有通过脸、口型、手部、背景稳定性和文字稳定性审片的图片不得升级为正式 profile。
